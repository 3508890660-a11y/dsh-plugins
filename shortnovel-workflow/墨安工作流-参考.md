## 二、各阶段方法学要点

### 1. 脑洞（brainstorm）
- 用短篇网文风格构建设定，**开头暴击**、标新立异、突破常规、语不惊人死不休；强悬念/反转/猎奇设定。
- 但要**贴近日常生活**、容易代入；每条脑洞情绪基调与输入保持一致，可换人名/换剧情。
- 每条脑洞必须包含：**男女主（核心角色）人设** + **完整梗概**（起因→经过→结果，开篇到完结）。
- 红线：禁止赛博朋克类、减少带系统脑洞；一次给 5 个；排版一句一行。
- 隐藏分析过程。

### 2. 导语（leadin）
- 一次裂变 **5 条**爆款导语；每条 **100–150 字**，是个“微型钩子”（不完读全文将彻夜难眠）。
- **黄金结构（禁止平铺）**：
  1. 矛盾前置爆破——首句抛出足以让拇指停滑的异常事实/致命选择；
  2. 背景闪回补刀——≤2 句，只给理解反转所需最低信息量；
  3. 反转致命一击——结尾彻底颠覆前文认知（身份置换/时间错位/因果倒置/规则崩坏）。
- 进阶传播学：情绪过山车（3 句内共情→疑惑→惊悚/狂喜/愤怒）、社交病诱饵（可引发争吵的价值观缝隙）、反套路碾压（对穿越/重生/霸总/系统等规则扭曲）、画面即视感（具象动词+感官名词）。
- 红线：开篇 20 字内须有动作或对话；禁“有一天/很久以前”等无效状语；禁机械降神/梦境解围；背景堆砌 ≤30%；禁说教/哲理结尾。
- 自检三联：疲惫用户会停下吗？营销号会截图做标题吗？至少 3 个具体疑问？

### 3. 大纲（outline）
- **10 章节 × 每章 10 个剧情点**；每章走通 **初始事件→引入冲突→设置障碍→制造转折→推向高潮→引出新的冲突**。
- 每个小剧情完成后引出要克服的阻碍/冲突；具体、可直接成文；每个环节制造强冲突、推进剧情、催读。
- 叙事渲染氛围、塑造人物，穿插对话/心理/环境；整体网文爽文：节奏紧凑、悬念迭起。
- **题材公式**（本插件按 `genre` 自动套用，见 `types.ts` 的 `genreFormula`）：
  - 追妻虐爽：第一章拉情绪 / 2–3 章让读者生气(猛虐) / 4 章高潮·付费点+主角醒悟抽身 / 反差感+情绪(猛虐)+火葬场。
  - 世情爽：第一章拉仇恨(凄惨对比) / 2 章爆发矛盾 / 3 章压情绪+第一波反击(穿插狗血) / 4 章硬核反击 / 拉仇恨+反击+反转+复仇。
  - 言情甜宠：按字数定位 导语50–200 暧昧 / 0–2000 开篇矛盾 / 2000–5000 卡点付费 / 5000–8000 高潮·互相试探·小虐制造危机 / 8000–10000 误会 / 10000–12000 大结局反转·甜度拉满 → CP感+反差感+情绪(暧昧/甜)。
  - 惊悚悬疑：导语50–200 猎奇 / 1000–2000 展开案件 / 3000–4000 卡点付费(我成了杀人嫌疑犯) / 5000–7000 透露一点真相 / 8000–10000 幕后boss+奇怪点 / 10000–12000 结局反转大逆转或再度跌宕。

### 4. 正文（novel）
- 篇幅 **10–12 章、约 1–1.2 万字**；严格**一句一段 / 一句一行**、每句 ≤30 字、手机竖屏适配。
- **首句无缝衔接导语**；遵循“黄金三章”，开篇即高潮。
- 统一**第一人称“我”**；语言精简干练口语化，大白话推剧情，严禁水文。
- **修辞禁令**：禁过度语气修饰（缓缓地/轻轻地/深情地）、禁空洞虚词（一丝/一抹/一缕）、禁标签化外貌神态（坚定的眼神/绝美的脸庞）、禁抽象比喻（她的笑容像阳光一样）、禁说教。统一中文标点。
- **节奏**：快准狠，每 **200–300 字**内一个钩子/情绪转折；围绕**付费点**（约全书 25–35%，即第四章前后）埋钩子。

### 5. 审稿（review）
- 以专业爆款短篇编辑「知小才」视角，给详细修改方案，排版清晰简洁。
- 满足**商品文商业价值、引导付费欲望**：设置一个**付费点（第四章左右，约 3000–4000 字处）**，并对其后各章节也提修改方案。
- 修改方案列出**修改后的详细文本**，**修改处加粗**；最终**输出完整修改后的短篇小说全文**，勿中断。

## 三、本插件落地形态

- 阶段：`brainstorm(脑洞) → leadin(导语) → outline(大纲) → novel(正文) → review(审稿)`，逐阶段确认（advance/revise）。
- 脑洞/导语各产出 5 条，用户可用 `revise` 反馈「选第 N 个」定稿。
- `novel` 阶段为**目标制**：`outline` 阶段在产出可读大纲的同时，末尾输出一个 fenced JSON「正文目标清单」（8–12 条，每条含 title/targetChars/beats/hook）；插件解析后存为 `project.goals`，正文按目标**逐段完成**（每段一个目标：目标字数+关键剧情点+钩子要求），全部目标完成才进入 `review`。解析不到 JSON 时回退为字数制（按 targetChars 分块续写），旧项目不受影响。
- `revise` 在正文阶段只重写当前段（不重写已完成目标段）；`status` 显示「正文目标 N/M（当前：…）」。
- `review` 满意 → `advance` 标记整本完成（done）。
- 题材公式由 `genreFormula(genre)` 按关键字自动匹配：追妻虐爽 / 世情爽 / 言情甜宠 / 惊悚悬疑 / 通用兜底。
- **文风卡（style-kb）**：项目可经 `shortnovel_style_kb` 绑定/启用 style-kb/cards 里的文风卡/手法卡，启用的卡蒸馏成「文风指引块」自动注入脑洞/导语/大纲/正文/审稿各阶段；也可在 `shortnovel_generate` 传 `styleCards` 本次临时覆盖。短篇硬约束（一句一行、去AI味、开头暴击、付费点）优先于文风卡模仿。
- 数据与 Codes 见 `src/types.ts`、`src/generator.ts`、`src/tools.ts`、`src/store.ts`、`src/style-kb.ts`。

## 四、提示词注入位点（微调入口）

- 人设（贯穿各阶段）：`generator.ts` → `AUTHOR_SYSTEM`。
- **文风卡蒸馏与注入**：`style-kb.ts` → `StyleKb` / `distillCard` / `distillKeys`；`generator.ts` → `styleBlock` / `stageSys`（每张 ≤700 字符，默认单次最多 3 张，可通过 `shortnovel_generate` 的 `styleCards` 或 `distillKeys` 的 `capChars/maxCards` 调整）。
- **去 AI 味·通用负面提示词（黑名单）**：`generator.ts` → `DEAI_NEGATIVE`，已并入 `AUTHOR_SYSTEM`，**自动作用于全部阶段**（脑洞/导语/大纲/正文/审稿）。涵盖：AI腔/翻译腔/公众号腔、空泛套话、机械排比、充数虚词、模板过渡、强行升华说教、自我重复注水。
- **正文/叙事专用·去 AI 味负面提示词（Show don't Tell + 反流水线）**：`generator.ts` → `PROSE_BANS`，注入 正文 与 审稿 两个阶段的改稿提示；含 判定词偷懒、模板神态（皱眉/勾唇/眼底一暗）、万能意象、长句套句、省略号叹号刷情绪，以及墨安五条修辞禁令。
- 题材公式：`types.ts` → `ZHUIQI / SHIQING / TIANCHONG / XUANYI / GENERAL`。
- 阶段要点（展示用）：`types.ts` → `STAGE_GUIDE`。

> 微调建议：若某题材（如甜宠）本身允许偏"精致文风"，可在正文 prompt 里适度放宽 `PROSE_BANS` 中的部分禁项；但 `DEAI_NEGATIVE`（AI/翻译/公众号腔）建议全题材默认保持强制。
